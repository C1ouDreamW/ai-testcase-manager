# AI 用例管理平台 接口文档

- Base URL：`http://127.0.0.1:8000/api`
- 数据格式：请求与响应均为 JSON（文件上传使用 `multipart/form-data`，导出接口返回文件流）
- 错误格式：`{"detail": "错误描述"}`；参数校验失败返回 422（FastAPI 标准结构）
- 在线调试：服务启动后访问 `/docs`（Swagger UI，仅 `DEBUG=true` 时开放）

## 鉴权

除 `POST /auth/login`、`POST /auth/register`、`GET /health` 外，所有接口都要求携带登录后颁发的 token：

```
Authorization: Bearer <token>
```

- token 由登录 / 注册接口返回，有效期由 `AUTH_TOKEN_TTL_HOURS` 配置
- 会话保存在后端进程内存中，服务重启后需要重新登录
- 缺失或失效时返回 `401 {"detail": "登录已失效，请重新登录"}`

## 通用状态码

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 201 | 创建成功 |
| 204 | 删除成功（无响应体） |
| 400 | 业务校验失败（如未确认功能点就生成、文件类型不支持） |
| 401 | 未登录或 token 失效 |
| 403 | 无权限（如未开放注册） |
| 404 | 资源不存在 |
| 409 | 资源冲突（如用户名已存在） |
| 422 | 请求参数校验失败 |
| 429 | 触发频率限制（登录失败锁定、注册过于频繁） |
| 502 | LLM / Embedding 调用失败（Key 过期、限流、网络异常等，`detail` 为中文提示） |

## 2. 登录认证 Auth

前缀：`/auth`（`login` 与 `register` 为公开接口，无需 token）

### POST /login

```json
// 请求
{ "username": "tester", "password": "your-password" }
// 响应
{ "token": "64 位十六进制字符串", "user_id": 1, "username": "tester", "is_admin": false }
```

- 用户名或密码错误返回 401
- 同一来源 IP 连续失败达到 `AUTH_MAX_ATTEMPTS` 次后锁定 `AUTH_LOCKOUT_MINUTES` 分钟，期间返回 429（响应头带 `Retry-After` 秒数）

### POST /register — 201

```json
{ "username": "tester", "password": "at-least-8-chars" }
```

约束与错误：

| 场景 | 状态码 |
|---|---|
| `ALLOW_REGISTRATION=false` 未开放注册 | 403 |
| 用户名已存在 | 409 |
| 同一 IP 每小时注册超过 `REGISTRATION_MAX_PER_HOUR` 次 | 429 |
| 用户名 3~32 字符（字母 / 数字 / 下划线 / 短横线）、密码 8~128 字符不满足 | 422 |

注册成功即登录，响应结构同 `POST /login`。

### POST /logout — 204

注销当前会话。token 取自 `Authorization` 头，也兼容请求体 `{ "token": "..." }`。

## 4. 需求文档 Requirements

### POST `/{document_id}/confirm`

### PATCH `/{document_id}/scope`

```json
{ "test_scope": "{\"in_scope\":[],\"out_scope\":[\"第三方登录\"],\"risks\":[\"锁定阈值待确认\"]}" }
```

### POST `/{document_id}/scope/generate`
AI 生成测试范围建议，写入 `test_scope` 并返回文档。

### 功能清单导入导出

## 4.1 设计稿 Designs

前缀：`/projects/{project_id}/designs`。设计稿必须关联同一项目下已导入的需求文档。

- `GET ?document_id={id}`：返回设计资产及其 `insights[]`；资产含 `parse_source`（`mock` 或 `vision:{模型名}`），用于区分示例数据与真实视觉解析。
- `POST /upload`：multipart 上传，字段为 `document_id`、`file`；支持真实 PNG / JPG / WebP，最多 8 张、单张 ≤10MB。
- `POST /figma`：保存 Figma 官方链接，请求体为 `document_id`、`url`、`title`（可选）；首版不读取远程画板。
- `GET /{asset_id}/content`：鉴权读取原始设计稿图片。
- `POST /{asset_id}/parse`：调用视觉模型提取设计功能点；已配置视觉模型时一律真实调用（与生成模型 Mock 解耦）；仅未配置视觉且开启 LLM Mock 时返回示例数据并标记 `parse_source=mock`。Figma 链接不能直接解析。
- `PATCH /insights/{insight_id}`：编辑或勾选设计功能点，可更新 `page`、`module`、`feature`、`description`、`acceptance_criteria`、`constraints`、`priority`、`selected`。
- `POST /merge?document_id={id}`：请求体 `{\"insight_ids\":[1,2]}`；将选中 insight 去重合并为 `RequirementItem`，来源标记为 `design`，并使文档回退到 `structured`。
- `DELETE /{asset_id}`：删除尚未合并的资产、解析结果和本地图片，204；已有功能点合并时返回 400，以保留来源。

图片文件保存在 `DESIGN_ASSET_DIR`（默认 `backend/data/design-assets`）；API 响应和数据库不包含 base64 图片。

## 5. 用例生成 Generations

前缀：`/projects/{project_id}/generations`

### POST `` — 201

```json
{
  "document_id": 1,
  "strategy": "full",              // full | quick
  "specialist_skills": ["security"], // 可选：security / api_test
  "use_knowledge": true            // 开启 RAG 检索
}
```

前置校验：文档必须为 `confirmed`，否则 400。任务异步执行，通过轮询获取进度。

### GET `/{task_id}`
任务详情：`status`（pending/generating/completed/failed）、`progress`（0~100）、`stage`（阶段文案）、`tokens_used`、`strategy_config`（工作流/Skill/模型/RAG 的非敏感配置快照）、`knowledge_refs`（RAG 溯源 JSON）、`drafts[]`（候选用例）、`quality_report`（质检报告）、`review_stats`（评审统计）。

草稿字段：`title`、`priority`、`case_type`（functional/boundary/exception）、`is_smoke`、`precondition`、`steps`（JSON 数组字符串）、`expected_result`、`quality_status`、`review_status`（pending/adopted/rejected/edited）、`reject_reason`、`was_edited`、`judge_score`（1~5）、`judge_issues`。

### GET ``
任务列表（含草稿）。

### GET `/summary`
生成记录摘要：`draft_count`、`smoke_count`、`coverage_rate`、`review_stats`、`document_title`，不含草稿明细。

### POST `/{task_id}/pause`
请求协作式暂停：仅 `generating` 可暂停（评测任务不可）。状态先变为 `pausing`，当前 LangGraph 节点完成后写入检查点并变为 `paused`。幂等：已是 `pausing`/`paused` 时直接返回。

### POST `/{task_id}/resume`
允许恢复 `failed` 或 `paused` 状态任务。通过运行租约 CAS 防止并发双跑；LangGraph 从最近成功检查点继续。其他状态返回 400，租约冲突返回 409。

任务状态：`pending` → `generating` → `pausing` → `paused` → `generating` → `completed` / `failed`。

### POST `/{task_id}/review`

```json
{ "draft_ids": [1, 2], "action": "adopt" }                          // 采纳，返回入库用例列表
{ "draft_ids": [3], "action": "reject", "reject_reason": "重复场景" } // 驳回，返回 []
```

`action` 取值 `adopt` / `reject` / `to_confirm`，非法值返回 422。

### PATCH `/{task_id}/drafts/{draft_id}`
编辑草稿（字段均可选）：`title`、`priority`、`case_type`、`precondition`、`steps`、`expected_result`。编辑后 `review_status=edited`、`was_edited=true`。

### POST `/{task_id}/judge`
手动（重新）运行 AI Judge 评分，刷新草稿评分与质检报告汇总。

### GET `/{task_id}/export?format=xlsx|md&smoke_only=false`
导出候选用例文件流；无可导出用例返回 400。

## 7. 测试任务 Test Tasks

前缀：`/projects/{project_id}/tasks`

一个测试任务包含多个执行批次（如线下测试 / 预发测试 / 线上测试），批次内每条用例对应一条执行记录。

任务与批次响应均带 `stats` 执行统计：

```json
{ "total": 20, "passed": 15, "failed": 2, "blocked": 1, "pending": 2, "executed": 18, "pass_rate": 75.0 }
```

### 任务管理

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `` | 创建任务（同时创建首个批次），201 |
| GET | `` | 任务列表（按创建时间倒序，含批次） |
| GET | `/{task_id}` | 任务详情 |
| PATCH | `/{task_id}` | 编辑任务：`name` / `description` / `status`（in_progress / completed） |
| DELETE | `/{task_id}` | 删除任务（级联删除批次与执行记录），204 |
| GET | `/{task_id}/defects?include_blocked=false` | 任务级缺陷列表：聚合所有批次的失败（可选含阻塞）记录 |

创建任务请求体（`case_ids` 与 `source_task_id` 二选一，都缺失返回 422）：

```json
{ "name": "登录模块 v1.2 测试", "description": "", "batch_name": "线下测试", "case_ids": [1, 2, 3] }
{ "name": "登录模块 v1.2 测试", "batch_name": "线下测试", "source_task_id": 7 }  // 导入生成任务已入库的用例
```

`source_task_id` 对应生成任务没有已入库用例时返回 400。

缺陷列表项字段：`batch_case_id`、`batch_id`、`batch_name`、`case_id`、`title`、`priority`、`module`、`feature`、`result`、`note`、`defect_ref`、`executed_at`。

### 批次管理

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/{task_id}/batches` | 新建批次，响应为整个任务 |
| GET | `/{task_id}/batches/{batch_id}` | 批次详情，含 `cases[]` 执行清单 |
| PATCH | `/{task_id}/batches/{batch_id}` | 编辑批次：`name` / `status`（in_progress / completed） |
| DELETE | `/{task_id}/batches/{batch_id}` | 删除批次，204；任务至少保留一个批次，否则 400 |

新建批次请求体（`case_ids` 与 `copy_from_batch_id` 二选一）：

```json
{ "name": "预发测试", "copy_from_batch_id": 1 }   // 复用已有批次的用例集，执行结果重置
{ "name": "预发测试", "case_ids": [1, 2, 3] }      // 重新圈选用例
```

批次详情 `cases[]` 字段：`id`（执行记录 ID）、`case_id`、`title`、`priority`、`case_type`、`is_smoke`、`precondition`、`steps`、`expected_result`、`module`、`feature`、`result`、`note`、`defect_ref`、`executed_at`。

### 执行记录

前缀：`/{task_id}/batches/{batch_id}/cases`

| 方法 | 路径 | 说明 |
|---|---|---|
| PATCH | `/{batch_case_id}` | 标记单条执行结果 |
| PATCH | `/batch` | 批量标记（不覆盖已有备注与缺陷号） |
| POST | `` | 向批次追加用例（已存在的自动跳过） |
| DELETE | `/{batch_case_id}` | 从批次移除执行记录 |

```json
// 单条标记
{ "result": "failed", "note": "登录报 500", "defect_ref": "BUG-1024" }
// 批量标记
{ "batch_case_ids": [1, 2, 3], "result": "passed" }
// 追加用例
{ "case_ids": [4, 5] }
```

`result` 取值：`pending`（重置未执行）/ `passed` / `failed` / `blocked`；标记为非 pending 时记录 `executed_at`。以上接口均返回更新后的批次（含最新 `stats`）。

## 8. 知识库 Knowledge

前缀：`/projects/{project_id}/knowledge`

### POST `` — 201

```json
{ "title": "订单业务规则", "content": "# 订单模块\n## 退款规则\n...", "source_type": "doc" }
```

`source_type`：doc（业务文档）/ case（历史用例）/ defect（缺陷记录）。
入库流程同步完成分块与向量化；内容过短（不足最小分块长度）返回 400。

响应：`id`、`title`、`source_type`、`status`（ready/processing/failed）、`chunk_count`、`error_message`。

### POST `/upload` — 201
文件上传（multipart）：`file`（.md/.docx）、`title`（可选）、`source_type`（可选，默认 doc）。

### GET ``
知识文档列表。

### GET `/{doc_id}/chunks`
分块列表：`content`、`heading`（标题路径，如 `订单模块 > 退款规则`）。

### POST `/search`

混合检索：向量（语义）+ BM25（关键词）双路召回，RRF 融合排序；配置了 Rerank 模型时再做精排。

```json
// 请求
{ "query": "退款手续费怎么算", "top_k": 5 }
// 响应
[ { "content": "...", "title": "订单业务规则", "heading": "订单模块 > 退款规则", "source_type": "doc", "score": 0.83, "match": "both" } ]
```

- `match`：命中来源，`vector`（语义）/ `keyword`（关键词）/ `both`（双路命中）
- `score`：未配置 Rerank 时为向量相似度（仅关键词命中的结果为 0）；配置后为精排相关性分
- 向量路过滤相似度低于阈值（0.35）的结果；Rerank 调用失败时自动退化为融合排序

### DELETE `/{doc_id}` — 204
删除文档并清理向量。

## 9. 测试助手 Agent

前缀：`/projects/{project_id}/agent`。项目内问答助手：只读查询用例/覆盖率/进度/缺陷/知识库，并支持设计稿受控写入（解析 → 展示 → 确认 → 合并）。

### POST `/chat` — SSE 流式

```json
// 请求
{
  "question": "请解析这些设计稿",
  "document_id": 12,
  "asset_ids": [3, 4],
  "attachments": [
    { "asset_id": 3, "asset_type": "image", "title": "登录页", "filename": "login.png" },
    { "asset_id": 4, "asset_type": "figma", "title": "Figma", "figma_url": "https://www.figma.com/design/xxx" }
  ],
  "reply_to_id": 88
}
```

仅附件无文字时，服务端使用默认问题「请解析这些设计稿并列出功能点，等待我确认后再合并。」。
可选 `reply_to_id`：引用同项目下某条历史消息；服务端会把引用摘要注入模型上下文，并写入用户消息的 `reply_to_id`。

响应为 `text/event-stream`，每条 `data:` 为一个 JSON 事件：

| 事件 type | 字段 | 说明 |
|---|---|---|
| `user_message` | `id` | 本轮用户消息已落库的 ID |
| `tool_start` | `name`、`input` | 开始调用工具 |
| `tool_end` | `name`、`output?` | 工具结束，可含输出摘要 |
| `token` | `content` | 回答增量文本 |
| `done` | `content`、`tool_calls[]`、`pending_insight_ids[]`、`id`、`user_message_id` | 本轮结束；`id` 为助手消息 ID |
| `error` | `message` | 模型调用失败 |

- 附件必须属于当前项目与目标需求；Figma 仅关联展示，截图负责视觉解析
- 合并须用户确认（前端确认卡片或工具 `merge_design_insights(confirmed=true)`）
- Mock 模式：无附件走知识库剧本；有截图附件走解析演示并返回 `pending_insight_ids`

### GET `/messages`

历史对话（旧→新，最多 50 条），含 `attachments`、`document_id`、`pending_insight_ids`、`reply_to_id`、`reply_to`（被引用消息摘要）。

### DELETE `/messages` — 204
清空该项目的全部对话记录。

## 11. 系统设置 Settings

### GET /settings
返回五套模型配置（生成 / 视觉 / 评测 / Embedding / Rerank）；API Key 仅返回 `*_api_key_set`（是否已配置）与 `*_api_key_masked`（掩码），不回显明文。

### PATCH /settings
字段均可选，只更新提交的字段：

```json
{
  "llm_api_key": "sk-xxx", "llm_base_url": "https://api.deepseek.com/v1",
  "llm_model": "deepseek-v4-flash", "llm_mock_mode": false,
  "eval_llm_api_key": "", "eval_llm_base_url": "", "eval_llm_model": "",
  "vision_api_key": "", "vision_base_url": "", "vision_model": "",
  "embedding_api_key": "", "embedding_base_url": "", "embedding_model": "",
  "rerank_api_key": "", "rerank_base_url": "", "rerank_model": ""
}
```

- 评测模型留空时回退使用生成模型配置；视觉模型不回退，真实模式下未配置时不能解析设计稿
- Embedding 未配置时知识库在 Mock 模式下走伪向量
- Rerank 模型留空时知识检索只做混合检索融合排序，不做精排
- 评测 / 视觉 / Rerank 的三元组（地址、模型、Key）必须全填或全空，否则返回 400

### POST /settings/test
测试模型连通性：

```json
// 请求
{ "target": "generation" }   // generation | vision | eval | embedding | rerank，默认 generation
// 响应
{ "ok": true, "message": "", "model": "deepseek-v4-flash", "base_url": "https://api.deepseek.com/v1" }
```
